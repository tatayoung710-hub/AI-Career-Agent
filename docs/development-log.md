# 分阶段交付记录

## Step 1 · 产品与需求

**完成：** 明确用户资料、岗位收集、匹配、简历版本、沟通辅导、投递管理和每日队列流程；把渠道许可、真人与 AI 身份、发送回执定义为产品边界。

**为什么：** 求职结果不能通过伪造经历或把“已生成”当成“已投递”来衡量。

**知识点：** 用户旅程、产品范围、验收标准、第三方平台权限与结果状态机。

**面试题：** 为什么没有把每日 1000 写成已投出 1000？

**回答：** 1000 是可配置队列目标。平台实际提交能力受接口授权和配额限制，所以我分别记录材料准备、发送尝试、邮件服务器接受和招聘方确认，避免虚报。

## Step 2 · 项目结构与接口契约

**完成：** 建立 `frontend/`、`backend/`、`database/`、`docs/`、CI、容器和本地启动脚本；采用 `/api/v1` JSON API 与 JWT。

**为什么：** 将界面、业务服务、持久化和文档边界分开，便于本地运行、测试与部署。

**知识点：** React + TypeScript、FastAPI 分层、REST、容器、配置外置、身份验证。

**面试题：** JWT 放在哪里，如何隔离数据？

**回答：** 前端只在当前浏览器会话保存短期访问令牌，API 从令牌识别用户；所有用户资源查询都加 `user_id` 过滤，并由组合外键约束跨用户引用。

## Step 3 · 数据库

**完成：** 设计 21 个实体，涵盖事实及修订、文件、来源、岗位快照、简历证据、投递事件、AI 调用、策略、批次、任务和消息。

**为什么：** 保存每次定制所依据的岗位和事实版本，使建议与申请可以追溯。

**知识点：** PostgreSQL、SQLAlchemy、Alembic、复合外键、不可变快照、唯一键和乐观锁。

**面试题：** 如何避免简历后续更新覆盖已投版本？

**回答：** 每次保存创建新的 ResumeVersion，并冻结 JD 与事实快照；审核、导出和投递记录都关联具体版本。

## Step 4 · 后端 API 与任务队列

**完成：** 认证、资料、岗位、来源、文件、简历、导出、投递、建议和每日策略 API；PostgreSQL 持久任务表、独立 Worker、租约、心跳、幂等键、暂停和结果未知处理。

**为什么：** 长时间 AI 与批次任务在 API 重启后仍可恢复，发送前崩溃也不会盲目重试。

**知识点：** FastAPI 依赖注入、SQL 事务、`FOR UPDATE SKIP LOCKED`、租约与幂等、乐观并发控制。

**面试题：** Worker 在 SMTP 成功后崩溃，系统如何避免重复邮件？

**回答：** 发送前先持久记录 `sending` 尝试。租约失效时改记 `unknown`，要求人工核实，不把外部发送放进自动重试。

## Step 5 · 前端

**完成：** 响应式中文工作台，包含登录、总览、经历、来源、岗位、简历编辑、投递看板、AI 教练、自动化和设置。

**为什么：** 用户能检查事实、证据、岗位要求和批次状态，而不是只得到一个不可审阅的生成结果。

**知识点：** React Hooks、TypeScript API 类型、表单校验、JWT 请求、异步状态、Tailwind 响应式布局。

**面试题：** 如何处理过期令牌与 API 错误？

**回答：** API 层统一处理状态码和结构化错误；401 清理会话并通知界面重新登录，其他错误显示服务端说明。

## Step 6 · AI

**完成：** OpenAI Responses API 结构化输出用于多轮对话、回答点评、JD 提取、加权证据匹配、简历生成、语义审查和沟通草稿；未配置密钥时显式返回 503。

**为什么：** 结构化结果可以校验、展示和保存。事实引用、确认状态、经历类型和数字由确定性规则复核，语义支持另行调用 AI 审查。

**知识点：** Pydantic schema、提示词边界、事实溯源、语义校验、超时、并发限制、敏感资料最小化日志。

**面试题：** Pydantic 结构合法是否意味着简历内容真实？

**回答：** 不是。schema 只保证形状；我还验证事实归属、用户确认、数字和经历类型，再对每条主张做独立语义支持核查，并保留人工批准步骤。

## Step 7 · 验证与交付

**完成：** 建立后端 pytest、Ruff、Alembic 检查与 GitHub Actions；本机 5 项工作流测试和前端 TypeScript/Vite 生产构建通过。

**为什么：** 针对真实风险检查事实约束、账户流程、冲突更新和批次幂等，而不仅是验证组件能渲染。

**知识点：** API 集成测试、内存隔离数据库、CI PostgreSQL 服务、构建产物与可复现依赖。

**面试题：** 哪些结果还不能称为已验证？

**回答：** 真实 OpenAI 网络调用、生产 PostgreSQL 运行、第三方招聘平台提交以及招聘方申请回执都需要对应凭证或渠道授权。项目不会把未配置的集成写成通过。
