# 产品需求与实现原则

目标用户：大学生、应届生、希望按岗位调整求职材料的求职者。

核心流程：资料上传 → 用户确认事实 → 岗位与来源导入 → 证据匹配 → 岗位专属简历
→ 人工审阅导出 → 投递记录 → 面试与HR沟通复盘 → 下一步建议。

## 功能

- PDF / DOCX / TXT资料上传，提取原文，明确处理扫描PDF、损坏、加密和超限文件。
- 事实库区分教育、工作、项目、技能、兴趣；修改创建新版本。
- 粘贴JD、手动录入、CSV/XLSX导入；支持每天新增公众号、小程序、网站和表格来源。
- 文字点评输出哪里有问题、原因、修改建议；HR关注点明确为基于原话的推测。
- 多轮AI对话，个人事实和目标岗位作为上下文。
- 针对岗位生成中文、英文、教师、运营、外企和国际岗位风格；事实不随风格改变。
- 简历模板、版本、编辑、批准、PDF/DOCX/TXT导出。
- 投递看板：待投递、已投递、HR沟通、一面、二面、Offer、拒绝；保存事件和具体简历版本。
- 每日批次：可配置目标≤1000、筛选、预算、运行时间、渠道、暂停；材料/尝试/回执分计。

## 事实约束

“帮助老师整理资料”不能无依据增加“优化教学流程”或百分比成果。
“关注Google产品”与“关注Prada”属于兴趣；具体工具实践或品牌分析成果必须另有事实。
每条主张引用用户确认的事实；引用只证明来源，不能证明真实性。
四要素（行为、问题、方法、结果）用于追问与整理，缺失信息不强行补齐。

## 匹配分

JD要求默认权重：明确要求3、一般要求2、加分项1。
证据：充分支持1、部分支持0.5、资料未提供0、明确不满足0。
分数为加权覆盖度，不是录用概率；硬性条件、未知和真实缺口分别显示。
保存要求、语义关联和规则版本，确保冻结输入后评分可复算。

## 来源登记

初始来源仅登记入口，不表示已读取全部数据或获得自动发送能力：

- 飞书：【秋招/春招/实习】汇总表-婉清学姐。
- 腾讯文档：互联派名企校招2。
- 微信公众号：牛客汇总（用户提供名称，账号入口尚待核验）。
- 求职方舟、OfferShow网站/小程序、牛客校招日程。

来源获取与投递执行分开。公司级校招线索需要展开到具体JD和官方入口。
BOSS、小程序等未确认许可的渠道只提供材料与入口，不虚构成功回执。

## 验收

没有依据的机构、职位、职责、技能与成果不能进入正式导出。
AI未配置仍能管理事实、来源、岗位、简历和投递状态。
批次结果待核实时不盲重试；内部千条容量成绩与真实渠道发送成绩分别报告。
所有API、文件、版本和任务按用户隔离。
